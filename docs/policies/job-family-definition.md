## 0. 이 문서의 위치와 근거 원칙

### 0-1. 위치

- 이 문서가 직무군 정의의 원본이다. 코드는 같은 값을 설정값으로 읽는다. 값을 바꿀 때는 이 문서를 먼저 고치고 코드에 옮긴다.
- 직무군이 20개를 넘거나 대표 키워드를 자주 고치게 되면 키워드는 `job_families.csv`로 옮기고, 이 문서에는 정의·경계 기준 같은 문장만 남긴다 (03 문서 0장).
- 항목의 뜻과 작성 원칙은 03 문서 3-2를 따른다. 이 문서에는 값만 적는다.

### 0-2. 근거 원칙: 공식 근거 중심

직무군 정의는 팀이 임의로 정한 분류가 아니라 **공식 직무 분류를 출발점**으로 구성한다.

| 순서 | 근거 | 쓰는 곳 | 이유 |
|---|---|---|---|
| 1 | **NCS 세분류와 능력단위** | 정의, 핵심 결과물, 대표 키워드 | 국가가 고시한 직무 표준이다. 능력단위 이름(예: "경영계획 수립", "프로젝트 일정관리")이 그 직무가 실제로 수행하는 업무 단위이므로, 결과물과 키워드를 여기서 가져온다 |
| 2 | **사람인 직무 코드표** | 사람인 소분류 연결 | 공고에 실제로 붙는 분류다. 매핑표(`job_family_map.csv`)와 이어지는 지점을 확인한다 |
| 3 | 정책문서 (03 문서 2-1) | NCS에 맞는 세분류가 없는 부분 | "결과물이 같으면 같은 직무"라는 기준 문장으로 빈 곳을 채운다 |
| 4 | 샘플 공고 | 검증만 | 정의가 기대 판정(03 문서 7-1)을 내는지 확인하는 데만 쓴다. 정의의 출처로 쓰지 않는다 |

- 각 직무군의 `근거` 항목에 위 순서 중 무엇을 썼는지 적는다. NCS 근거가 부분적이거나 없는 항목은 그렇다고 표시한다.
- NCS 분류번호는 `대분류-중분류-소분류-세분류` 8자리이고, 능력단위는 10자리다 (예: `02010101` 경영기획, `0201010103` 경영계획 수립).
- **NCS 확인 방법:** 위 고시 별첨에서 분류번호를 검색한다. 확정할 때는 ncs.go.kr 분류별 검색에서 같은 분류번호와 능력단위가 현행인지 다시 확인한다. 이 초안은 고시 별첨으로만 확인했다 (ncs.go.kr 화면에서는 대분류 목록까지만 확인).

### 2-1. `JF_SERVICE_PLANNING` 서비스기획

| 항목 | 값 |
|---|---|
| 정의 | 사용자가 쓰는 서비스의 기능, 화면, 이용 흐름을 설계하고 개발·디자인이 만들 수 있도록 요구사항으로 정리한다 |
| 핵심 결과물 | 요구사항 정의서(PRD), 화면 설계서·와이어프레임, 스토리보드, 서비스 시나리오, 서비스 정책서, 기능 명세 |
| 대표 키워드 | 서비스 기획; 서비스 설계; 화면 설계; 화면 구성; 와이어프레임; 요구사항 정의; 기능 정의; 개발 요건; 사용자 흐름; 흐름 설계; 워크플로우 설계; 서비스 시나리오; 서비스 정책; 예외 처리; PRD; 인터랙션 정의 |

| 지원 상태 | 지원 |
| 근거 | NCS(부분) + 정책문서 2-1 |

**NCS 근거 (부분)**

NCS에는 업종에 상관없는 "서비스기획" 세분류가 없다. 서비스기획의 업무는 아래 세 세분류에 나뉘어 있고, 정의는 이 능력단위들의 공통 부분에서 가져왔다.

| NCS 세분류 | 분류 경로 | 서비스기획과 겹치는 능력단위 |
|---|---|---|
| `20010702` 인공지능서비스기획 | 정보통신 > 정보기술 > 인공지능 > 인공지능서비스기획 | `2001070205` 인공지능 서비스 시나리오 기획, `2001070209` 인공지능 서비스 요건 정의, `2001070204` 인공지능 서비스 모델 기획 |
| `20010207` UI/UX엔지니어링 | 정보통신 > 정보기술 > 정보기술개발 > UI/UX엔지니어링 | `2001020702` UI/UX 계획 수립, `2001020704` UI/UX 요구 분석, `2001020705` UI/UX 콘셉트 기획, `2001020706` UI 아키텍처 설계 |
| `10030102` 전자상거래 | 영업판매 > 판매 > e-비지니스 > 전자상거래 | `1003010203` 사이트 기획 |

- 인공지능서비스기획은 AI 서비스에 한정된 세분류지만, 샘플 1번·3번(AI 에이전트 서비스 기획) 공고의 업무(시나리오·요건 정의)와 가장 가깝다.
- 응용SW엔지니어링(`20010202`)에도 `2001020224` 화면 설계가 있다. NCS는 화면 설계를 개발 업무로도 본다. 그래서 "화면 설계"가 나와도 결과물이 설계서인지 구현된 화면인지로 가른다 (5-2의 4단계, AI 판별).

| 경계 기준 | `JF_SERVICE_PLANNING`: 계획 대상이 회사 전체면 경영기획, 특정 서비스의 기능이면 서비스기획 |

| 근거 | NCS |

**NCS 근거:** `02010101` 경영기획 (경영·회계·사무 > 기획사무 > 경영기획 > 경영기획)

| 능력단위 | 정의·결과물에 반영한 내용 |
|---|---|
| `0201010102` 경영방침 수립, `0201010103` 경영계획 수립 | 경영 방침과 목표, 경영계획서 |
| `0201010105` 사업별 투자 관리, `0201010106` 예산 관리 | 예산·투자 배분 |
| `0201010107` 경영실적 분석 | 실적 분석, KPI 보고서 |
| `0201010104` 신규사업 기획 | 키워드에 넣지 않음 (아래 참고) |

- NCS는 `0201010104` 신규사업 기획을 경영기획의 능력단위로 둔다. 그래서 사람인 소분류 사업기획(1633)·신사업기획(1664)은 경영기획과 서비스기획 양쪽으로 읽힌다. 이 둘은 키워드에 넣지 않고 문맥 판별 대상(03 문서 3-4)으로 처리한다.

**NCS 근거:** `01010102` 프로젝트관리 (사업관리 > 사업관리 > 프로젝트관리 > 프로젝트관리)

| 능력단위 | 정의·결과물에 반영한 내용 |
|---|---|
| `0101010201` 프로젝트 전략기획, `0101010202` 프로젝트 통합관리 | 프로젝트 계획서 |
| `0101010204` 범위관리, `0101010206` 일정관리, `0101010207` 원가관리, `0101010205` 인적자원관리 | 범위·일정·인력·원가 계획 |
| `0101010208` 리스크관리, `0101010203` 이해관계자관리, `0101010210` 조달관리 | 리스크·이해관계자·조달 관리 |

- NCS 프로젝트관리는 업종을 가리지 않는 세분류다. 사람인에는 IT 외에 임상PM(804) 같은 PM도 있다. **업종은 IT·서비스 프로젝트로 한정한다 (2026-10-28 결정, 3장 3번).** 연구 과제(R&D), 건설, 임상시험 같은 다른 업종의 프로젝트 관리는 결과물이 일정·인력·원가 계획이어도 `범위외`로 본다. 임상PM(804)은 지원 대분류 밖이라 매핑표에 없다.
- "PM"은 키워드에 넣지 않았다. 사람인 기획·전략 대분류에 PM(프로젝트매니저)(1649)과 PO(프로덕트오너)(1651)가 따로 있지만, 공고 직무명의 "PM"은 Product Manager로도 쓰인다.

## 4. 샘플 공고 키워드 점검

매핑표를 채우기 전에 대표 키워드만으로 샘플 공고 6건(03 문서 7-1)을 판정해 본 기록이다.

**방법**

1. 업무 항목마다 대표 키워드가 들어 있는지 찾는다. 공백을 지우고 비교한다 (03 문서 5-2).
2. 후보 직무군이 하나면 바로 라벨을 붙이고, 없거나 둘 이상이면 AI 판별로 넘긴다 (03 문서 5-2의 3·4단계).
3. AI는 7-1의 기대 라벨을 맞힌다고 가정하고, 과반으로 판정해 7-1과 비교한다.

**결과**

| | 수정 전 키워드 | 수정 후 키워드 (현재) |
|---|---|---|
| 기대 판정과 다른 공고 | **3번 1건: 일치가 아니라 불일치로 나옴 (거짓 불일치)** | 없음 (6건 모두 기대 판정) |
| 키워드만으로 잘못 붙은 라벨 | 3개 (3번 항목 2·4·5가 "구현" 때문에 개발로 붙음) | 1개 (1번 항목 4, 아래 참고) |
| AI로 넘어간 항목 | 25개 중 14개 | 25개 중 11개 |

**고친 키워드**

| 직무군 | 뺀 키워드 | 넣은 키워드 | 이유 |
|---|---|---|---|
| 개발 | 개발, 구현, 코딩, 배포, 파이프라인 구축 | 기능 개발, 에이전트 개발, 서버 개발, API 개발, 설계·개발, 설계 및 개발, 유지보수, 파이프라인, 코드 작성 | 기획 공고의 "구현 화면 초안", "구현 범위 조율"이 개발로 잘못 붙었다. 2번 공고의 "인덱싱 파이프라인 확장"은 "파이프라인 구축"에 걸리지 않았다 |
| 서비스기획 | | 서비스 설계, 화면 구성, 개발 요건, 흐름 설계, 워크플로우 설계 | 3번의 "화면 구성안", "개발 요건 작성", "서비스 설계에 재반영"과 1번의 "워크플로우 설계", "흐름 설계"가 걸리지 않았다 |
| 경영기획 | | 경영 성과 | 6번의 "경영 성과를 관리"가 걸리지 않았다 |
| 영업 | 거래처 발굴 | 거래처 | 5번의 "거래처를 발굴"처럼 조사가 끼면 걸리지 않는다 |

"기획 문서"도 서비스기획 키워드로 검토했지만 넣지 않았다. 문서 작성은 공통 업무이고, 개발 공고의 "기획 문서를 읽고 구현"에도 걸린다.

**남은 문제: 공통 업무는 키워드로 걸러지지 않는다**

- 1번 항목 4("협업 & 커뮤니케이션")는 7-1에서 `공통`이지만, 문장 안의 "서비스 기획에 반영" 때문에 서비스기획으로 바로 붙는다.
- 판정 결과(일치)는 같다. 하지만 서비스기획 공고의 협업 항목은 대부분 "서비스 기획"이라는 말을 포함하므로, 공통 항목이 서비스기획으로 세어지는 경향이 생긴다. 이 경우 오류는 거짓 일치 쪽으로 난다.
- 해결 (2026-10-27): 03 문서 5-2에 공통 단서 확인 단계를 추가했다. 후보 탐색 뒤에 공통 단서(03 문서 3-2 표)를 확인하고, 하위 업무에 공통 단서가 있으면 AI 판별로 넘긴다. 키워드는 하위 업무(`/`·문장) 단위로 찾고, 항목 라벨은 `공통`이 아닌 하위 업무가 절반을 넘을 때만 직무군으로 한다. 이 점검은 항목 단위 텍스트로 했으므로 하위 업무 단위 점검은 설정값을 코드로 옮긴 뒤 다시 한다.

**데이터분석·QA 키워드 추가 후 재점검 (2026-10-26):** 2-8, 2-9의 대표 키워드를 샘플 6건의 주요 업무 항목에 공백을 지우고 대 보았다. 걸리는 항목이 없다. 샘플 1번 "데이터 분석 & 개선"과 6번 "경영 데이터의 추적/취합/분석"은 계속 `공통` 후보이고, 3번 "결과 검증"은 서비스기획으로 남는다.

**한계:** AI가 항상 맞힌다고 가정했다. 샘플 6건에 맞춰 고친 키워드라서, 검증용 공고 20~30건에서 다시 확인해야 한다.

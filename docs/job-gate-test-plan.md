## 0. 시작 전 결정 (2026-10-28 확정: 추천안대로)

- [x] **공고 수:** 60건을 **개발셋 30건 / 확인셋 30건**으로 나눈다. 키워드와 5-3 기준값은 개발셋만 보고 고친다. 확인셋은 마지막에 한 번만 돌린다. 샘플 6건처럼 맞춰 고친 데이터로 다시 채점하는 문제를 피하기 위해서다. 검색어별로 10건씩, 유형이 고르게 섞이게 나눈다.
- [x] **정답 작성 방식:** Claude가 항목 분리·라벨·판정·근거를 **초안(`draft`)**으로 쓰고, 사용자가 검토해 **확정(`approved`)**한다 (매핑표와 같은 방식). 6-2는 정답을 문서 작성자가 먼저 쓴다고 정하므로 테스트는 `approved` 정답으로만 채점한다.
- [x] **mock의 한계:** mock은 AI 자리에 정답 라벨을 넣는다. 그래서 이번 지표는 "AI가 항상 맞힌다고 가정한 상한"이다. mock으로도 실제로 측정되는 것은 **규칙이 AI 없이 확정한 라벨의 오답**과 **AI 호출 비중**이다. 실제 AI 지표는 AI 연결 후 같은 테스트를 `--ai`로 다시 돌려 얻는다.

## 1. 데이터 준비

- [x] 원티드 형식의 항목 분리 규칙을 03 문서 5-2 1단계 표에 추가한다 (문서 먼저). → 5-2 "목록형 공고의 항목 정리" (2026-10-28)
  - `[메인 업무]`, `[서브 업무]` 같은 구역 제목은 항목이 아니다.
  - 소제목과 그 아래 `•` 목록을 합쳐 항목 1개로 센다 (샘플 1번의 굵은 소제목과 같다). `•` 하나하나는 하위 업무다.
  - 소제목 없이 `•`만 있으면 `•` 하나가 항목 1개다.
  - 회사·포지션 소개 문장은 뺀다.
- [x] 변환 스크립트: `wanted_jds.json` → 판정 입력 형식(직무명 + 항목 목록)으로 변환한다. 자격요건(`requirements`)과 우대사항(`preferred_points`)은 게이트 입력에서 뺀다. 다시 돌려도 기존 정답은 보존된다.
- [x] 변환 결과에서 항목 분리가 잘못된 공고를 눈으로 확인하고 규칙을 고친다. 고친 것: 일반 문장 줄의 "이 직무에서 얻을 수 있는 것"도 멈춤 표시로 인식, "합류 후 기대하는 결과"·"이런건 하지 않아요" 구역 제외, 내용 문장이 글머리표 줄 아래에 붙지 않게 함.
- [x] 비슷한 공고 쌍은 하나는 개발셋, 다른 하나는 확인셋에 넣는다 (`SPLIT_PAIRS`).
- [x] 개발셋·확인셋을 나누고 목록을 기록한다. 각 셋 30건, 검색어별 10건. 목록은 `eval_cases.json`의 `set` 필드.
  - 유형 균형 조정: 번갈아 나누니 서비스기획 일치 공고가 확인셋에 몰려 개발셋 `일치` 정답이 2건뿐이었다. 같은 검색어 안에서 2쌍을 맞바꿨다 (`FORCE_SET`: 핀브릿지 서비스 PM ↔ 해양 R&D 기획자, 클라우드 서비스 기획 및 운영 ↔ 럭셔리 이벤트 기획).

## 2. 정답 작성 (6-2)

- [x] 개발셋 30건 정답 초안: 공고마다 항목별 라벨, 핵심 직무군, 게이트 판정(희망 직무 = 서비스기획), 근거 한 줄, 확신도(높음/보통/낮음). 모두 `review_status=draft` (2026-10-28). 일치 4, 불일치 12, 범위 외 9, 검토 필요 2, 보류 3.
- [x] 판단이 어려운 공고는 정답을 임의로 정하지 않고 **보류 목록**에 사유와 함께 남긴다 (6-2). 개발셋에서 보류 3건이 나왔고 모두 사용자 판단으로 해소했다. 보류는 현재 0건.
- [x] 사용자 검토 → `approved` (개발셋 30건, 2026-10-28). 고친 정답에는 사유를 `note`에 남겼다. 검토에서 바뀐 것: 어쎈드(→ 불일치 개발), 유트랜스퍼(→ 범위 외), 어딩(→ 일치), 치즈에이드(→ 일치), 플레어랩스(→ 일치), 서비스 운영 항목 공통 처리.
- [ ] **자격요건 정답은 따로 둔다 (6-2).** 칸만 만들고 비워 둔다. 자격요건 평가 코드가 없어 게이트 테스트에는 쓰지 않는다. **보류 (2026-10-28):** 자격요건 평가 문서 확정 뒤에 채운다.
- [x] 확인셋 30건 정답 **초안**을 썼다 (2026-10-28, 모두 `draft`). 초안 분포는 일치 3, 불일치 16, 범위 외 10, 검토 필요 1이었다. **검토 후 `approved` 확정 (2026-10-28): 일치 3, 불일치 14, 범위 외 12, 검토 필요 1. 확신도 높음 16, 보통 14.**
  - 이 과정에서 변환 규칙의 결함 2건을 확인셋 항목 분리에서 발견해 고쳤다 (링크 줄이 항목으로 들어감, "기술 스택 선정" 문장이 구역 제목으로 오인됨). 개발셋의 항목은 영향이 없음을 확인했다.

## 1. 프로젝트 목적 (2p)

**챗봇이나 발표용 데모가 아닌, 실제 업무를 해결하는 협업형 AI 에이전트 MVP**를 만든다.
사용자가 입력한 정보를 바탕으로 여러 단계의 작업을 수행하고 결과물을 생성하는 시스템을 설계·개발·검증한다.

1. **문제 정의** — 실무 프로세스를 분석해 자동화 가능한 과제를 정의
2. **빠른 구현** — 바이브 코딩으로 프로토타입을 빠르게 구현
3. **협업 워크플로** — 여러 역할의 에이전트가 협력하는 흐름 구성
4. **실사용 검증** — 정확성·사용성·비용·보안 측면에서 활용 가능성 검증
5. **운영 인계** — 회사가 재현·수정·운영할 수 있는 형태로 인계

## 2. ★ 우리 팀: 2팀 — AI 취업 준비 통합 에이전트 (3p, 5p) ★

### 2-1. 팀 개요
- **핵심 사용자:** 취업준비생
- **최종 결과물:** 공고 탐색 · 매칭 · 자소서 · 포트폴리오
- **시스템 정의:** 구직자의 이력·희망 직무·보유 역량을 기반으로 **공고 탐색부터 지원 서류·포트폴리오 초안까지** 지원하는 시스템

### 2-2. 에이전트 역할 (4개)

| 역할 | 이름 | 내용 |
|---|---|---|
| 역할 01 | **프로필 분석** | 이력서·경험·기술·희망조건 구조화 |
| 역할 02 | **채용 공고 탐색** | 공개 채용 정보 또는 허용된 API·샘플 데이터 활용 |
| 역할 03 | **적합성 평가** | 직무요건과 경험 비교, 부족 역량과 근거 제시 |
| 역할 04 | **지원서·포트폴리오** | 공고별 자기소개서, 프로젝트 소개, 포트폴리오 초안 |

### 2-3. 필수 MVP 시나리오 (반드시 처음부터 끝까지 동작해야 함)

```
가상 지원자 프로필 1개
  → 채용공고 5건 비교
  → 적합성 순위 및 이유
  → 선택한 공고의 자기소개서·포트폴리오 초안 생성
```

### 2-4. 주의사항 (반드시 준수)
- **경력·학력·자격증 창작 금지.** 입력된 프로필에 없는 내용을 만들어내지 않는다.
- **공고 수집 허용 범위와 개인정보 보호 원칙을 준수**한다.
- **매칭 점수는 참고용**이며, 점수가 나온 이유를 **설명 가능**해야 한다.

### 2-5. (참고) 다른 팀 프로젝트 — 3p 요약
- **1팀** AI 제안서 작성 에이전트 — 사업개발·제안 담당자 / 공고 분석부터 제안서 초안까지
- **3팀** AI 교육 커리큘럼 기획 에이전트 — 교육기획자·강사 / 교육 수요 분석·과정 설계·강의계획서·실습안
- **4팀** AI SNS 콘텐츠 발행 및 노출 최적화 에이전트 — 마케팅·홍보 담당자 / 콘텐츠 기획·채널별 변환·발행 예약·성과 분석

## 3. 기술 및 비용 운영 원칙 (8p~9p)

### 3-1. 기술 원칙: "도구는 팀 수준에 맞게, 목표는 동작하는 MVP" (8p)

**개발 도구**
- VS Code, Git/GitHub, Python
- Streamlit 또는 간단한 웹 UI
- 바이브 코딩: Cline 등 모델 연결형 확장 검토

**에이전트 프레임워크**
- Google ADK, CrewAI, LangGraph 중 선택
- 단순한 파이썬 함수 기반 역할 분리도 허용
- **프레임워크 사용 자체가 목표는 아님**

**모델 후보**
- Gemini, GLM, DeepSeek 등
- 무료 제공 여부·사용량 한도·국가·계정·결제 조건은 수시로 변동

> ⚠️ **반드시 확인:** 2026년 10월 기준 **공식 요금표 및 약관**을 팀별로 직접 확인한다. **무료 API와 무료 채팅 서비스는 다르다.**

### 3-2. 비용 규칙: "무료부터 시작하고, 결제는 승인 후에" (9p)

| 번호 | 구분 | 규칙 |
|---|---|---|
| 01 | 기본 원칙 | 초기에는 **무료 티어·로컬 모델·모의 응답(mock)** 을 우선 사용 |
| 02 | 기본 원칙 | **API 키는 코드·저장소에 올리지 않고** `.env`와 비밀 관리 기능 사용 |
| 03 | 기본 원칙 | 모델별 **호출 횟수·토큰 사용량·예상 비용**을 기록 |
| 04 | 보고 | 무료 한도 소진 시 **무단 결제 금지**, 팀장 및 담당자에게 보고 |
| 05 | 사전 승인 | 유료 API, 유료 클라우드, 외부 SaaS 결제는 **사전 승인** |
| 06 | 별도 승인 | 회사 내부 자료·개인정보·고객 자료를 외부 AI API로 보낼 때는 **별도 승인** |

## 4. 수행 일정과 운영 (10p)

**4주 수행 일정 (예시, 실제 기간에 맞춰 조정)**

| 주차 | 단계 | 내용 | 점검 산출물 |
|---|---|---|---|
| 1주차 | 1단계 | 사용자 문제 정의, 현행 프로세스, MVP 범위, 개발환경 구축 | 요구사항 정의서 · 화면 흐름 · 테스트 데이터 |
| 2주차 | 2단계 | 역할별 에이전트 구현, 입력·출력 연결, 기본 UI | 작동하는 첫 번째 프로토타입 |
| 3주차 | 3단계 | 에이전트 간 연계, 품질 검증, 오류·비용 최적화 | 통합 MVP · 테스트 기록 |
| 4주차 | 4단계 | 사용자 시연, 실무 피드백, 수정, 문서화 | 최종 시연 · 코드 · 매뉴얼 · 성과보고서 |

**운영 리듬**
- **매일:** 오전 10분 스탠드업(어제 결과 · 오늘 목표 · 장애요인), 오후 작업 기록 업데이트
- **매주:** 실제 동작 데모 1회 (**슬라이드만으로 보고 금지**), 피드백 후 다음 주 우선순위 확정

## 5. 공통 개발 요구사항 — 모든 팀이 지켜야 할 8가지 (11p)

| 번호 | 항목 | 내용 |
|---|---|---|
| 01 | **다단계 처리** | 입력 → 추출/탐색 → 분석/판단 → 초안 생성 → 검토/출력 |
| 02 | **역할 분리** | 최소 3개 이상의 역할·단계 구분. **무조건 LLM 호출을 늘리는 것은 금지** |
| 03 | **근거 제시** | 외부 사실·공고·통계에 **원문 링크 또는 문서명과 확인일** 기록 |
| 04 | **사용자 확인** | 중요한 결정·발송·제출·수정은 **자동 실행하지 않고 승인 단계** 거침 |
| 05 | **예외 처리** | API 오류·자료 누락·한도 초과 시 **안내와 재시도 방법** 제공 |
| 06 | **재현 가능성** | 신규 담당자가 **설치 안내서만 보고 실행** 가능 |
| 07 | **평가 가능성** | **정상·오류·불완전 입력 포함 테스트 케이스 5개 이상** 정의·기록 |
| 08 | **모델 교체 가능성** | **LLM 호출 모듈을 분리**해 모델별 비교가 가능하도록 |

## 6. 최종 제출물 8종 (12p)

1. 실행 가능한 MVP와 소스코드 저장소
2. README (설치·환경변수·실행·사용법)
3. 시스템 구조도 및 에이전트 역할 정의서
4. 사용한 데이터·API 목록과 라이선스/이용 조건
5. 테스트 케이스 5건 이상과 성공·실패 결과
6. 모델별 품질·속도·비용 비교표 (비교 가능할 때)
7. 3~5분 실제 작동 시연 영상 또는 현장 시연
8. 최종 보고서: 문제 정의, 구현 기능, 한계, 실무 적용 제안, 향후 개선사항

## 7. 평가 기준 — 총 100점 (13p)

**"화려함보다 실제 작동과 신뢰성"**

| 항목 | 배점 | 평가 질문 |
|---|---|---|
| 실무 활용성 | **30** | 실제 사용자에게 필요한 업무를 해결하는가? |
| 기능 완성도 | **25** | 핵심 시나리오가 처음부터 끝까지 동작하는가? |
| 결과 품질·신뢰성 | **20** | 근거·정확성·예외 처리 수준이 충분한가? |
| 비용·운영 효율 | **15** | 무료 자원을 효율적으로 활용하고 비용을 측정했는가? |
| 문서화·협업 | **10** | 다른 사람이 유지보수할 수 있는가? |

> **평가 원칙:** 모델이 답변을 잘 생성하더라도 **검증 불가능한 결과는 높은 점수를 받을 수 없다.**

## 8. 첫날 수행 과제 (14p~15p)

### 8-1. 오늘 할 일 6가지 (14p)
1. 핵심 사용자와 **가장 큰 불편 3가지** 정의
2. 실제 **입력 예시 1개**와 **기대 출력 예시 1개** 작성
3. **필수 기능 3개**와 제외할 기능 구분
4. 에이전트별 역할 및 **업무 흐름도** 작성
5. 사용할 AI 모델·API의 **무료 조건과 데이터 처리 정책** 확인
6. 당일 종료 전 **5분 이내**로 팀별 개발 계획 공유

### 8-2. 팀별 첫날 보고 양식 (15p)
**Markdown으로 작성해 당일 종료 전 공유한다.**

```markdown
# [팀명] 개발 계획

- 프로젝트명:
- 해결할 문제:
- 주요 사용자:
- 입력 데이터:
- 기대 출력:
- 필수 기능 3가지:
- 에이전트 역할 및 연결 흐름:
- 개발 도구 / 모델 / API:
- 무료 사용 조건 확인 결과:
- 개인정보·보안 위험:
- 첫 주 데모 목표:
- 역할 분담 (2명):
- 예상 장애요인 및 지원 요청:
```

- [ ] README만 보고 신규 담당자가 설치·실행할 수 있는가?
